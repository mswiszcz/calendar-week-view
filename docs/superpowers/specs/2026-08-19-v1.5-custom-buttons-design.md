# calendar-week-view 1.5 — custom header & floating buttons

Status: approved (goal-directed). Date: 2026-08-19.

## Goals

1. `headerButtons` — user-defined buttons at the **top-right** of the header,
   vertically centered in the header row.
2. `floatingButtons` — user-defined buttons **beside the floating +** at the
   bottom-right (a row, custom buttons to the left of the +).
3. Each button fires a standard Home Assistant action (`navigate`, `url`,
   `call-service`, `more-info`, `toggle`) via `custom-card-helpers` `handleAction`.
4. Release as 1.5.0.

## Config surface (`src/types.ts`, editor)

New shared shape and two optional `CardConfig` lists:

```ts
export interface ButtonConfig {
  icon: string;              // MDI icon (required)
  name?: string;             // header: label; floating: tooltip/aria
  color?: string;            // optional accent for the icon (and header chip)
  tap_action?: ActionConfig; // HA action; absent → renders but no-op
}
// CardConfig gains:
headerButtons?: ButtonConfig[];
floatingButtons?: ButtonConfig[];
```

All optional; any pre-1.5 config keeps working unchanged.

Editor: a new **Buttons** expansion panel with two add/remove lists (Header,
Floating) mirroring the Calendars pattern. Per button an `ha-form` exposes
`icon` (icon selector), `name` (text), and `tap_action` (native
`selector: { ui_action: {} }` action editor), plus the shared color swatch/text
pair. Empty optional keys are stripped on save (`_cleanButton`).

## Interaction rules

- A button with no `tap_action` renders but does nothing on click (tolerates
  partial editor state).
- `floatingButtons` are independent of `addEvents`: the bottom-right `.fab-row`
  renders whenever there are floating buttons **or** the quick-add `+` is shown.
  The `+` (when present) stays the rightmost, accent-filled hero.
- `headerButtons` render inside a right-aligned `.topbar-right` group that also
  holds the legend and the calendar-view expand toggle, so all three share one
  vertically-centered right cluster. The former per-element `margin-left:auto`
  on `.legend`/`.expand-btn` moves onto `.topbar-right`.

## Rendering (`src/card.ts`, `src/card.styles.ts`)

- `_runButton(btn)` → `handleAction(this, this._hass, { entity: '', tap_action }, 'tap')`.
- `_renderHeaderButtons()` → `.header-actions` of `.hbtn` pill chips; icon +
  optional `.hbtn-label`; `--c` sets the icon color.
- `_renderFabRow()` → `.fab-row` (absolute, bottom-right) containing `.fbtn`
  round icon buttons (48px, neutral surface) then the existing `.fab` `+` (56px).
- `.fab` loses its own absolute positioning; `.fab-row` positions the cluster.

## Testing

The vitest suite covers pure week/weather logic only; the buttons are
declarative config→render with no pure logic to unit-test. Verified via the
`make verify` gate: `pnpm test` (61 pass), `pnpm typecheck`, `pnpm lint`,
`pnpm build`.
