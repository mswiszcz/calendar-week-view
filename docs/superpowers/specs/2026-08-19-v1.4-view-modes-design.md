# calendar-week-view 1.4 — highlight toggle, decoupled header, lock-to-today, vertical layout

Status: approved (goal-directed). Date: 2026-08-19.

## Goals

1. `highlightToday` (default true) — off drops today's background tint, keeping the accent
   day-number and border so today stays identifiable.
2. When navigation isn't shown, remove the carousel's side padding (arrow gutter).
3. Decouple the clock and the next-event: `showClock` = clock + date only; new
   `showNextEvent` (default true) controls the upcoming-event chip independently.
4. `lockToday` (default false) — disables all navigation and renders `visibleDays` days
   starting at today (1 → today only, N → today-anchored window). Fetches only that range.
5. `orientation` (`horizontal` | `vertical`, default `horizontal`) — agenda layout axis.
   Horizontal is the current strip; vertical stacks days full-width and scrolls down.
6. Release as 1.4.0.

## Config surface (`src/types.ts`, editor)

Four new `CardConfig` keys: `highlightToday?: boolean`, `showNextEvent?: boolean`,
`lockToday?: boolean`, `orientation?: 'horizontal' | 'vertical'`. All optional; the card
keeps working with any pre-1.4 config unchanged, except that a pre-1.4 `showClock: false`
now hides only the clock+date — add `showNextEvent: false` to also hide the upcoming chip.
Editor: add the four to `GENERAL_SCHEMA` + `LABELS`; `orientation` is a two-option select.

## Interaction rules

- `orientation` affects **agenda view only**. Calendar (time-grid) view keeps its horizontal
  day-columns regardless — a stacked per-day time-grid would be unusably tall.
- `lockToday` forces navigation off (arrows, return glyph, paging, recenter all suppressed),
  in both orientations and both view modes.
- Carousel side-padding is removed whenever navigation is absent: `showNavigation === false`
  **or** `lockToday`.
- The status header renders when `showClock` **or** `showNextEvent` is on, **or** when a
  return glyph is due (`showNavigation && !lockToday && today off-screen`), so the
  return-to-today affordance survives even with clock and next-event both off.

## 1. highlightToday (`src/card.ts`, `src/card.styles.ts`)

Host class `nohighlight` (added when `highlightToday === false`). CSS neutralizes today's
fill in both views — `ha-card.nohighlight .day.today` falls back to `--neutral-tile`, and
`.day.cal.today .cal-head` / `.day.cal.today .grid` drop the `--today-tint` background —
while keeping the border and the accent `.dnum` / `.cd-num` so today is still legible.

## 2. Carousel padding (`src/card.ts`, `src/card.styles.ts`)

`classMap` on `.carousel` adds `nonav` when navigation is absent; `.carousel.nonav`
zeroes the horizontal padding so the strip spans the full card width.

## 3. Decoupled clock / next-event (`src/card.ts`)

`_renderStatus` splits into two independently-gated parts: clock + date under `showClock`,
the upcoming chip under `showNextEvent`. `_refreshUpcoming` and the header tick timer gate on
`showClock || showNextEvent` (the countdown still needs ticks when the clock is hidden;
`_scheduleClock` → `_scheduleTick`). The header container renders per the interaction rule
above. `_renderReturn` stays under `showNavigation`.

## 4. lockToday (`src/week.ts`, `src/card.ts`)

New pure, tested `lockedDays(today, count, hideWeekend)` in `week.ts`: `count` consecutive
days from `today` (>= 1), skipping weekend days when `hideWeekend`. When `lockToday`,
`_fetchAndBuild` builds columns from `lockedDays` (fetching only that span) instead of the
buffered multi-week `windowDays`, and the seamless-window machinery (recenter, scroll-to-today,
`_windowOffset`) is bypassed. Arrows, return glyph, and paging are not rendered/allowed.

## 5. Vertical orientation — unified axis (`src/card.ts`, `src/week.ts`, `src/card.styles.ts`)

> **Superseded (v1.4.6):** vertical no longer reuses the seamless Y-axis scroller. It renders
> a static `lockedDays(now, visibleDays)` span (like `lockToday`), each day at its full
> content height with no inner scroll, and grows the card to fit — the dashboard scrolls, not
> the card. `_isStaticSpan()` gates the span/nav; `ha-card.vagenda` + `getGridOptions({rows:'auto'})`
> drive the growth. Paging arrows and return-to-today are not shown. The Y-axis carousel
> machinery below still exists for reference but is inactive in vertical agenda.

The horizontal carousel is a seamless infinite scroller (buffered 3-week window,
recenter-on-settle, native smooth paging). Vertical reuses that model on the Y axis rather
than adding a divergent scroll path.

- **Pure geometry (tested):** extract the index/position math from `card.ts` into pure
  `week.ts` functions over measured `number[]` offsets — `edgeIndex(starts, sizes, edge)`
  (first child past an edge), `lastVisibleIndex(starts, edge)`, `clampScroll(target, max)`.
  DOM reads stay in `card.ts`.
- **Axis accessor:** `_axis()` in `card.ts` returns the reader/writer set for the active
  orientation — `scrollLeft/clientWidth/offsetWidth/rect.left/{left}` for horizontal, the Y
  equivalents for vertical. `_leftmostIndex`, `_childLeft`, `_columnScrollLeft`, `_carousel`,
  `_recenter`, `_updateTodayVisibility`, and `updated()` go through it. Horizontal stays
  behaviorally identical (axis defaults to X).
- **Layout:** `.week.vert` is `flex-direction:column; overflow-y:auto; overflow-x:hidden`;
  `.day` is full-width, content-height; the per-day `.events` scroll cap is lifted in vertical
  so the whole strip scrolls as one. Arrows render top/bottom (horizontally centered) as
  up/down chevrons; return-to-today scrolls today to the top.
- `visibleDays` remains horizontal-only (column width) and the `lockToday` day-count; it does
  not constrain vertical free-scroll.
