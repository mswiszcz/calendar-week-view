# calendar-week-view 1.0.1 — visual editor, fill-height, event delete, custom colors

Status: approved (goal-directed). Date: 2026-08-19.

## Goals

1. Visual settings editor matching week-planner-card UX — manage calendars in the UI, no YAML.
2. Card fills the dashboard space in height.
3. Delete calendar events from the event overview modal.
4. Custom colors for UI elements.
5. Bolder event overview modal (impeccable pass).
6. Release as 1.0.1.

## 1. Visual editor (`src/editor.ts`)

Replace the `ha-form` + "edit YAML" note with a custom Lit editor of collapsible
`ha-expansion-panel` sections:

- **General** — `ha-form` for the scalar options (title, weekStartsOn, visibleDays,
  hideWeekend, height, showNavigation, showLegend, legendToggle, addEvents, compact,
  noCardBackground, combineSimilarEvents, updateInterval, timeFormat).
- **Calendars** — repeatable rows; each row: `ha-entity-picker` (domain `calendar`),
  name, color, filter regex, `hideInLegend` / `initiallyHidden`, and a remove button.
  An "Add calendar" button appends an empty row. No YAML required.
- **Weather** — `ha-entity-picker` (domain `weather`) + showTemperature / roundTemperature,
  with a clear button.
- **Quick add** — checkbox list selecting which configured calendars `addEventCalendars`
  allows the add dialog to write to.
- **Colors** — a color row per themeable element (see §4).

Editor emits `config-changed` with the full updated config on every edit; `setConfig`
validation stays in the card. A reusable `_colorRow` renders a native `<input type=color>`
plus an `ha-textfield` (so users can enter hex, a named color, or `var(--token)`).

## 2. Fill-height (`src/card.styles.ts`, `src/card.ts`)

`ha-card` becomes `height: 100%` with `min-height: var(--cwv-min-h)`; `.cwv` and `.week`
become flex columns that stretch. `.day` columns stretch to fill (drop the fixed
`--cwv-day-h` and today's +40px bump — today keeps its accent border/tint). Events scroll
inside a column when they overflow. The existing `height` option becomes the min-height
fallback (default 520px) so the card still looks right in masonry/sections views where the
container height is auto; in a panel view the card fills the viewport.

## 3. Delete events (`src/types.ts`, `src/week.ts`, `src/card.ts`)

Capture `uid` and `recurrence_id` from the REST response into `WeekEvent`. In the event
overview modal show a Delete button only when the event has a `uid` and its calendar exposes
`DELETE_EVENT` (supported_features bit `2`). Click → inline confirm → delete via
`hass.connection.sendMessagePromise({ type: 'calendar/event/delete', entity_id, uid,
recurrence_id })` (recurrence_id passed when present, deleting the single instance). On
success close and refetch; errors surface in the modal. No event editing, no recurring
this-vs-all choice (YAGNI).

## 4. Custom colors (`src/types.ts`, `src/card.ts`, `src/card.styles.ts`, editor)

Optional `colors` object; each key overrides an existing base token on the `ha-card`
element inline, so derived tints recompute automatically and unset keys keep theme defaults:

| config key | overrides | affects |
|---|---|---|
| `accent` | `--primary-color` | today accent, FAB, this-week button, nav hover, derived today tint |
| `today` | `--today-tint` | today column background |
| `dayBackground` | `--neutral-tile` | day column + legend chip background |
| `cardBackground` | `--card-background-color` | card + pill background base |
| `text` | `--primary-text-color` | primary text |
| `secondaryText` | `--secondary-text-color` | day-of-week, times, subtitles |
