# calendar-week-view 1.2.0 — status header, reliable Today, non-blocking paging

Status: approved (goal-directed). Date: 2026-08-19.

## Goals

1. Carousel arrows respond immediately; a running page animation never blocks a click.
2. Bold live clock in the top-left, with its own format setting (impeccable "bolder" pass).
3. **Today** reliably returns to today from any distance, not "this week scrolled to a side".
4. Date beside the clock; the Today button becomes a direction-aware return glyph, shown
   only when today is off-screen.
5. Next **upcoming event** with a live countdown, skipping all-day events except a
   tomorrow all-day when nothing remains today.
6. Release as 1.2.0.

## 1. Non-blocking paging (`src/card.ts`)

Native `scrollBy({behavior:'smooth'})` is ignored by some HA webviews when a smooth scroll
is already running, so a second arrow click does nothing until the first settles. Replace it
with a self-driven rAF pager: `_animateTo(strip, target)` eases `scrollLeft` toward
`_animTarget`, and the loop reads `_animTarget` every frame, so a click mid-animation just
retargets — clicks accumulate instead of no-op'ing. A `setTimeout` backstop lands the target
even where rAF is throttled (background tab), so paging and Today stay reliable everywhere.
`prefers-reduced-motion` jumps instantly.

## 2. Status header + clock settings (`src/card.ts`, `src/card.styles.ts`, `src/types.ts`, editor)

New top-left `.status` cluster, gated by `showClock` (default true): a bold live clock
(`clockFormat`, default `HH:mm`), the date (`headerDateFormat`, default `cccc, d LLLL`), and
the next upcoming event. A boundary-aligned timer (`_scheduleClock`) ticks per minute, or per
second when the format includes seconds. The clock is the impeccable "bolder" move — 40px/800,
tabular numerals, tight tracking — with the date and next-event kept quiet around it, reusing
the card's existing tokens and dot/pill motif (no new primitives).

## 3. Reliable Today (`src/card.ts`)

Root cause: `_windowOffset` is `@state`, so a Today reset rendered once with the old
(today-less) columns before the refetch resolved, and `updated()` consumed the
scroll-to-today intent on that stale frame — landing on index 0 ("this week, scrolled").
Fix: `updated()` positions only on the render that actually contains today (`idx < 0 →
return`), and a `_jumping` flag suppresses the seamless-window recenter until the jump lands.
`_goToday` animates to today's left edge when it is loaded, else resets the window to the
canonical offset, refetches, and hard-positions.

## 4. Date + return glyph (`src/card.ts`, `src/week.ts`, `src/card.styles.ts`)

`todayRelation(today, left, right)` (pure, tested) reports whether today is before/within/
after the visible day range, computed from the leftmost/rightmost visible columns on scroll,
paging, and jumps. The return button (part of `showNavigation`) renders only when today is
off-screen; its glyph is `mdi:calendar-arrow-left`/`-right` pointing toward today, and it
calls `_goToday`. Filled accent circle with an entrance animation.

## 5. Upcoming event (`src/week.ts`, `src/card.ts`)

`pickUpcoming(now, events)` and `formatCountdown(now, ev)` are pure and unit-tested.
`pickUpcoming` returns the nearest future timed event; all-day events are skipped except a
single all-day event starting tomorrow, surfaced only when no timed event remains today.
The header is now-anchored, not scroll-anchored: when the loaded window already covers today
it reuses those events; otherwise a small now-relative 14-day agenda is fetched (shared
`_fetchRange` helper) so the value stays correct while the strip is scrolled weeks away.
