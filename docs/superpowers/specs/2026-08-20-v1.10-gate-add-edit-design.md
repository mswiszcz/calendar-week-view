# calendar-week-view 1.10 — gate-style add / edit dialog (Version D)

Status: implemented (`make verify` green). Date: 2026-08-20.

Design reference: Gate Composer artifact, **Version D** — the "Live Gate, slim
header" comp (single-column form + slim coloured header, no countdown, start/end
datetime pickers). Screens: phone (bottom sheet) and desktop (centred 440 card),
add + edit, light + dark.

## Goals

1. Rebuild `calendar-week-view-add-dialog` in the **event-details "gate" world**:
   a calendar-colour band header, rounded neutral-tile fields, colour chips,
   segmented toggles, and the same `gate-in` entrance — replacing today's plain
   `ha-textfield` / `ha-select` / `mwc-button` stack.
2. Add **event name** clarity plus **location** and **description** inputs — none
   of which the dialog captures today, though the details popup already displays
   location + description.
3. Change timed events to a **start datetime** + **end datetime** model (each
   input carries its own date and time), which also enables **multi-day timed**
   events. All-day collapses to a single date.
4. Header shows the event's **concrete schedule**, not an "in X days" countdown —
   on an edit form the countdown is noise.
5. Persist name, location, description, and both datetimes through the existing
   `calendar.create_event` and `calendar/event/update` calls.
6. No change to the card's public surface: `show()`, `edit(e)`, and the
   `cwv-saved` event keep their signatures, so `src/card.ts` is untouched.
7. Release as 1.10.0.

## Data model — new pure module `src/event-payload.ts`

The dialog's schedule/service logic moves out of the element into a pure,
unit-tested module (the render stays in the element; `node` vitest has no DOM).

```ts
export interface EventDraft {
  summary: string;
  entity: string;        // target calendar (create only)
  allDay: boolean;
  date: string;          // 'YYYY-MM-DD'        — all-day
  start: string;         // 'YYYY-MM-DDTHH:mm'  — timed, local wall time
  end: string;           // 'YYYY-MM-DDTHH:mm'  — timed, local wall time
  location: string;
  description: string;
}

/** Service data for `calendar.create_event` (no entity_id — caller targets it). */
export function buildCreateData(d: EventDraft, zone: string): Record<string, string>;

/** The `event` object for a `calendar/event/update` message (base fields only;
 *  the caller adds the envelope, rrule, and recurrence scope). */
export function buildUpdateEvent(d: EventDraft, zone: string): Record<string, string>;

/** The header's concrete schedule line (no countdown, no "now" dependency). */
export function formatWhenLine(
  d: EventDraft, zone: string, timeFormat: string, locale?: string,
): string;

/** Null when the draft is saveable, else a user-facing reason. */
export function draftError(d: EventDraft, zone: string): string | null;
```

Behaviour (all timed parsing via `DateTime.fromISO(value, { zone })`):

- **buildCreateData** — always `summary` (trimmed). Adds `location` and
  `description` only when non-empty (trimmed). Then:
  - all-day → `start_date = d.date`, `end_date = d.date + 1 day` (HA's exclusive
    end; a single-day all-day event).
  - timed → `start_date_time = start.toISO()`, `end_date_time = end.toISO()`.
- **buildUpdateEvent** — `summary` (trimmed); `location` and `description`
  **always** included (trimmed, empty string clears a previously-set value, since
  edit prefills the fields); then:
  - all-day → `dtstart = d.date`, `dtend = d.date + 1 day`.
  - timed → `dtstart = start.toISO()`, `dtend = end.toISO()`.
- **formatWhenLine** — luxon formats with the config `timeFormat` (default
  `HH:mm`) and optional locale:
  - all-day → `"<ccc d LLL> · All day"`.
  - timed, same calendar day → `"<ccc d LLL> · <start> – <end>"`.
  - timed, spans days → `"<d LLL> <start> → <d LLL> <end>"`.
- **draftError** — `summary` empty → `"Add a name"`; timed with `end ≤ start`
  → `"End must be after the start"`; else `null`. (The primary button also stays
  disabled while the name is empty; `draftError` is the save-time guard and
  covers the datetime case the button can't.)

## Dialog state & logic — `src/add-event-dialog.ts`

Replace the `_start` / `_end` `HH:mm` fields with the datetime model and add the
two new inputs:

```ts
@state() private _allDay = true;
@state() private _date = '';        // all-day
@state() private _start = '';       // 'YYYY-MM-DDTHH:mm' timed
@state() private _end = '';         // 'YYYY-MM-DDTHH:mm' timed
@state() private _location = '';
@state() private _description = '';
@state() private _color = '';       // calendar colour → band --c
```

- `show()` (add) — seed `_entity`/`_calendarName`/`_color` from `calendars[0]`,
  `_date` = default date's ISO date, `_start` = default date at `09:00`, `_end`
  at `10:00` (both as `yyyy-LL-dd'T'HH:mm`). `_allDay = true` — the current
  default is preserved (no unrequested behaviour change); flip to `false` only if
  we decide timed-first is better. Clear name/location/description.
- `edit(e)` — additionally seed `_location = e.location ?? ''`,
  `_description = e.description ?? ''`, `_color = e.color`; timed →
  `_start = e.originalStart.toFormat("yyyy-LL-dd'T'HH:mm")`, `_end` likewise from
  `originalEnd`; all-day → `_date = e.originalStart.toISODate()`.
- Selecting a calendar chip sets `_entity`, `_calendarName`, and
  `_color = calendars.find(...)?.color ?? 'var(--primary-color)'`.
- `_save()` — build an `EventDraft` from state; if `draftError(draft, zone)` is
  non-null, set `_error` and stop; else call `_create` / `_update`.
- `_create()` — `hass.callService('calendar', 'create_event',
  buildCreateData(draft, zone), { entity_id: this._entity })`.
- `_update()` — `event = buildUpdateEvent(draft, zone)`, then attach `rrule` and
  the recurrence-scope envelope exactly as today, and send
  `calendar/event/update`.

`zone = this.hass.config?.time_zone ?? 'local'`. The countdown tick logic that
the *details popup* uses is **not** added here — the header schedule is static.

## Rendering — the gate structure (own shadow DOM)

The dialog is a separate custom element, so it cannot borrow `card.styles.ts`;
it gets its own copy of the needed gate CSS (see Styles). Mirror the details
popup's shell: `<ha-dialog open hideActions>` with fully custom content.

```
<ha-dialog open hideActions aria-label="Add event | Edit event">
  <div class="gate" style="--c:${_color}">
    <div class="band">                         ← slim coloured header (from comp 02)
      <div class="band-cal"><span class="swatch"></span>{calendarName}
           {recurring&&edit → repeat badge}</div>
      <input class="band-title" placeholder="Name this event" .value=${_title}>
      <div class="band-when"><ha-icon icon="mdi:calendar-clock-outline"></ha-icon>
           {formatWhenLine(...)}</div>
    </div>
    <div class="body">
      {_error && <ha-alert alert-type="error">}
      add  → Calendar chips (.cal-chips)
      edit → fixed calendar (.cal-fixed: dot + name + lock)
      When → segmented All day / Timed (.seg)
        all-day → <input type="date">
        timed   → <input type="datetime-local"> Starts, <input type="datetime-local"> Ends
      Where → <input type="text"> (optional)
      Notes → <textarea> (optional)
      edit && recurring → scope segmented (This / Following / All)
    </div>
    <div class="acts">
      Cancel(ghost) · spacer · {edit&&canDelete → Delete(danger)} · {Add | Save}(primary)
    </div>
  </div>
</ha-dialog>
```

- Icons: MDI via `ha-icon` (`mdi:calendar-clock-outline`, `mdi:calendar-blank-outline`,
  `mdi:clock-outline`, `mdi:map-marker-outline`, `mdi:repeat`, `mdi:lock-outline`,
  `mdi:close`, `mdi:plus`, `mdi:check`, `mdi:trash-can-outline`).
- Fields are styled native inputs (`.tin` tiles), not `ha-textfield`, to carry the
  gate aesthetic and give `datetime-local` its native pickers on mobile.
- Every input has an `aria-label`; the name input is the focus target on open.

## Interaction rules & decisions

- **All day vs timed** — the segmented toggle swaps the single date input for the
  Starts/Ends datetime pair; the header line and `draftError` follow.
- **Calendar** — add: chips, selecting recolours the band live. Edit: calendar is
  fixed (HA can't move an event between calendars); shown as a locked chip.
- **Multi-day timed** — supported for free: Starts and Ends carry independent
  dates; `end_date_time`/`dtend` land on the later day.
- **All-day stays single-date** (matches the comp). *Known limitation:* editing a
  pre-existing **multi-day all-day** event collapses it to one day on save, since
  only a start date is exposed. The card's own quick-add never created multi-day
  all-day events, so this affects only externally-authored ones. If we want to
  preserve them, a follow-up adds an all-day end-date field (flagged, not built).
- **Clearing location/description** — on edit these fields prefill; saving an
  emptied field clears it (empty string sent). Create omits empty fields.
- **Validation** — save blocked with an inline `ha-alert` when
  `draftError` returns a message (empty name, or `end ≤ start`).
- **Delete & recurrence scope** — unchanged: the scope selector shows only for a
  recurring event in edit mode and feeds `rrule` + `recurrence_range` as today.

## Testing — new `test/event-payload.test.ts`

Pure logic only (vitest `node` env), fixed `zone` (e.g. `'Europe/Warsaw'`):

- **buildCreateData**: timed → `start_date_time`/`end_date_time` in zone; all-day
  → `start_date` + exclusive `end_date` (= date + 1); `location`/`description`
  included when set, **omitted** when blank; `summary` trimmed.
- **buildUpdateEvent**: timed → `dtstart`/`dtend`; all-day → date + exclusive
  `dtend`; `location`/`description` **always present** (empty string when blank).
- **formatWhenLine**: all-day line; same-day timed line; day-spanning timed line;
  respects a custom `timeFormat` (e.g. `h:mm a`).
- **draftError**: empty name → message; timed `end < start` and `end == start`
  → message; valid timed and valid all-day → `null`.
